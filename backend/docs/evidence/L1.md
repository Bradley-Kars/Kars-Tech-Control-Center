## Staging Setup

### 1. Fresh Clone

```sh
mkdir -p ~/kts-staging
cd ~/kts-staging
git clone --branch work/web https://github.com/Bradley-Kars/Kars-Tech-Control-Center.git repo
cd repo
python3 -m venv .venv
source .venv/bin/activate
pip install -e backend
npm ci
npm run build
```

The backend looks for `dist/` at the repo root (`<repo-root>/dist/`), resolved via `Path(__file__).resolve().parents[2] / "dist"` in `backend/core/bridge.py`. The build output is at `~/kts-staging/repo/dist/` and is found correctly.

### 6. systemd Unit

Created `~/.config/systemd/user/kts-staging.service`:

```ini
[Unit]
Description=KTS bridge (ticketing API, loopback only)
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
WorkingDirectory=~/kts-staging/repo/backend
ExecStart=~/kts-staging/repo/.venv/bin/uvicorn core.bridge:app --host 127.0.0.1 --port 8798 --no-proxy-headers
Restart=on-failure
RestartSec=5
Environment="KTS_SANDBOX=1"
Environment="KTS_VAULT=~/kts-staging/data/vault"
Environment="KTS_HOME=~/kts-staging/data/home"
Environment="KTS_ALLOWED_HOSTS=<machine>.<tailnet>.ts.net"

[Install]
WantedBy=default.target
```

Enabled and started via `systemctl --user enable --now kts-staging.service`.

## Undo Instructions

- Stop staging service: `systemctl --user stop kts-staging.service`
- Disable staging service: `systemctl --user disable kts-staging.service`
- Remove unit file: `rm ~/.config/systemd/user/kts-staging.service && systemctl --user daemon-reload`
- Stop tailslate serve: `tailscale serve --https=8443 off`
- Remove staging directory: `rm -rf ~/kts-staging`
- Remove token: `rm ~/.config/kts/staging-token`

## Access

Staging URL: `https://<machine>.<tailnet>.ts.net:8443/` (tailnet only, accessible from any tailnet device)
