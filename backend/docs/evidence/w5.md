## W5 changes (all tested)

1. **`--no-proxy-headers`** (W5.1): Added to the `uvicorn` command in `backend/docs/DEPLOY.md` and the systemd unit example. `uvicorn` must not rewrite `request.client` from `X-Forwarded-For`, so the bridge's loopback check keeps trusting traffic proxied by tailscale serve.
2. **Integration test** (`backend/tests/test_proxy_headers.py`): Starts real `uvicorn core.bridge:app --no-proxy-headers` on a random port with sandbox env + fixture `users.yaml` and asserts:
   - valid login + `X-Forwarded-For` header → `200` (loopback still trusted, `X-Forwarded-For` ignored)
   - unknown login → `401`
   - no credentials → `401`
3. **`tailscale serve` instructions** (W5.2): `backend/docs/DEPLOY.md` now documents `tailscale serve --bg 8799` (tailnet-only HTTPS), Funnel never used, and tells the reader to confirm with `tailscale serve --help` and `tailscale serve status`. Removed the incorrect warning against `--https`.
4. **`TrustedHostMiddleware`** (W5.3): `allowed_hosts` = `localhost`, `127.0.0.1`, plus comma-separated `KTS_ALLOWED_HOSTS`. Forged host → `400`. For login-identified requests (no token) on unsafe methods (`POST`/`PUT`/`PATCH`/`DELETE`): `403` if `Sec-Fetch-Site` is `cross-site`, or if an `Origin` header is present whose host differs from the `Host` header. Token requests are unaffected. Tests: forged host `400`; cross-site POST with login `403`; same-origin POST with login `200`; token requests unaffected.
5. **Lowercase + strip** (W5.4): Both `users.yaml` login values and the `Tailscale-User-Login` header value are lowercased and stripped before comparison. Mixed-case test passes.
6. **Actor type** (W5.5): Login-identified requests get actor type `"human"` (name = the login). Token requests use type `"automation"` (default). `core/permissions.py` resolves roles for both (`human` and `automation` both map through `users.yaml` roles). Test: a login-identified write records actor type `human`.
7. **`actor_id` in success audit** (W5.6): `TokenTable.audit_request` now accepts and records `actor_id` on successful requests.
8. **Trust model** (W5.7): `backend/docs/DEPLOY.md` documents that loopback header trust means any local process can impersonate a login; acceptable only on a single-user host.
